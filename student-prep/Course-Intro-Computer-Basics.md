# Course Intro: Computer Basics (2 to 4 Hours)

A brief, instructor-led orientation for the first session or two of the course, since there is no pre-course basics class. It replaces the earlier self-study prep path.

The fleet is Mac-primary with some Windows, and some students have only used iPads. This is written for Macs, with Windows notes where they differ.

## The honest constraint

You cannot make an iPad-only student fully computer-fluent in a few hours. So this intro covers only the true prerequisites, the things that block everything else, and the rest is taught **just in time** during the course, at the moment it first matters. When a student saves their first Python file in Week 1, that is the folders-and-saving lesson. Right before the terminal unit, that is the paths lesson. Do not try to teach the whole office suite or the terminal here; the course handles those later.

This intro is part of the 50 to 55 instructional hours, not on top of them. At two hours a week it consumes roughly the first one to two sessions. The Unit 1 Python ramp picks up immediately after, and the compressed Unit 6 leaves room to absorb it.

## What to cover, and the time budget

Total about two and a half to three and a half hours, which fits your 2 to 4 hour window.

### Block A: Laptop and the file system (about 75 minutes, the core)
This is the block that matters. If you only get through this one, the intro succeeded.
- Trackpad: click, right-click (two-finger tap or Control-click), scroll.
- The desktop, the Dock, the menu bar; switching between open apps (Command+Tab).
- Finder and the sidebar (Documents, Downloads, Desktop).
- Create a folder, name it, put a file in it, close it, then find it again.
- Spotlight search (Command+Space).
- Copy, cut, paste (Command+C, X, V).

Outcome to check: each student can make a folder, save something into it, close it, and find it again, unaided.

Windows note: same block in File Explorer; shortcuts are Ctrl instead of Command, window switching is Alt+Tab.

### Block B: Browser and accounts (about 40 minutes)
- Open a browser; tabs; what a URL is; searching and judging results.
- Log in to the accounts the course uses (Google, Code.org). Do this together so nobody is stuck on Day 2.
- What a strong password is, and using the password manager (Bitwarden).

### Block C: First look at the real tools (about 40 minutes)
Tie the file system straight to coding so it sticks.
- Open Thonny. Type one line: `print("hello")`. Run it.
- Save the file into the folder from Block A. Close Thonny. Reopen the file from Finder.
- Optional: open a Google Doc so they have seen it before it is needed later.

Outcome: students have run code and saved a real file on their first day, which is motivating and reinforces the file system immediately.

## Run the readiness diagnostic here

Use the diagnostic from the Younger-Student Readiness and Prep guide during this intro. It takes a few minutes and tells you which students need the optional take-home videos below and extra attention in the first weeks. With no required prep, this early-warning is the main way you avoid a student silently falling behind.

## What to skip in the intro (taught just in time later)

- Word processing and spreadsheet depth. Not needed for the course itself; the course writes code in Thonny and VS Code and documents in Google Docs.
- The terminal. Unit 4 covers it, and Macs have it built in.
- Networking, saving to the cloud, file paths in depth. Each arrives with the unit that needs it.

## Optional take-home videos (voluntary, for families who want a head start)

Send these home as an offer, not a requirement. Especially useful for students the diagnostic flags.
- DigitalLearn (`training.digitallearn.org`): the macOS basics course, or the Windows 11 course. Short videos, absolute-beginner pace.
- Typing practice at typing.com or keybr.com, fifteen minutes a day. The single most useful thing a family can do in advance, since all coding depends on it.

## What is different from an iPad (say this out loud in Block A)

- There is a real file system. Files live in folders you navigate in Finder. An iPad hides this. This is the most important new idea.
- Right-click exists (two-finger tap or Control-click) and hides menus you will need.
- Windows overlap; several apps are open at once and you move between them.
- Saving is deliberate; you choose a name and a folder, and nothing auto-saves into an app the way it does on an iPad.
